# Safora `/docs` — how this folder is organised

```
docs/
  v1/   ← active V1 codebase & submission documentation (incl. comprehensive global industry research)
  v2/   ← post-V1 production roadmap (forensic dossiers, 112 CAD connector, offline packs, safety checks)
  v3/   ← future research files (AI routing, mesh SOS, AI image detection, voice-activated KWS, evaluation)
  setup.md   ← local dev setup guide
  SAFORA_Synopsis_Formatted.pdf   ← project synopsis document
```

## Reading order
1. `v1/README.md` → `v1/tasks.md` (V1 specifications & delivered features)
2. `v1/architecture.md`, `v1/api.md`, `v1/database.md`, `v1/dual-pipe-audio-streaming.md` (technical design & streaming protocols)
3. `v1/safora-v1-features-industry-research.md` (comprehensive audit of all 16 features, competitive benchmarks against Noonlight, RapidSOS, Citizen, SafetiPin, bSafe, UrSafe, and unique innovations)
4. `v1_manual_testing_checklist.md` (granular manual QA checklist across physical devices)
5. For post-submission roadmap: `v2/README.md` → `v2/roadmap.md` & `v2/safety-and-tracking.md` (court-admissible PDF dossier ADM-4, 112 ERSS connector ADM-5)
6. `v3/README.md` → `v3/06-voice-activated-sos.md` for faculty viva when asked about future research scope (DSP Keyword Spotting, AI routing, mesh networks).
